# 本地存储维护

## 范围

本策略在不删除权威发布包、Git 跟踪结论或主张解释证据的前提下，缩小 Research Guard 源码工作树与已安装插件缓存。清理必须串行、禁用 GPU，并遵守项目统一的 `512 MiB` 自有工作集上限。

## 分类与保留

| 类别 | 示例 | 必须执行的操作 |
| --- | --- | --- |
| 权威来源 | 已跟踪源码、注册表、文档、最终发布校验和 | 保留 |
| 精确重复 | 与规范副本精确 SHA-256 相同的重复下载 | 只保留一个规范副本，并记录映射 |
| 有用但暂时不用 | 被忽略的评测回执、快照、会场二进制 | 压缩一次，检查 CRC 与路径，写入 `SHA256SUMS.txt`，再删除原件 |
| 可复现缓存 | `build/`、`dist/`、可选 payload、已安装插件副本 | 核验权威发布包或锁定的再水合清单后删除 |
| 只需保留结论的原始数据 | 已取代的隔离安装和探针目录树 | 保留结论、计数、哈希、主张边界与恢复来源，删除原始副本 |

执行顺序必须是先归档、后删除。文件名相同、字节数相同或目录大小相近都不是去重证据；文件级去重必须依赖精确 SHA-256 相等。

## 清理流程

1. 记录仓库提交、文件数、字节数、磁盘可用空间与候选根目录的精确路径。
2. 核验候选项只能位于已准入的仓库、插件缓存、quarantine 或显式归档根目录下；不得对用户目录或工作区根目录做递归清理。
3. 将唯一最终发布集移到工作树外的归档目录，不做二次压缩。
4. 串行压缩冷证据；逐项测试 ZIP 的 CRC，并拒绝绝对路径或包含 `..` 的条目。
5. 保留双语归档说明、精简结论账本和校验和。
6. 只删除已核验候选项。Windows 若残留超过 260 字符的路径，应显式枚举并逐一清除，不得扩大目标范围。
7. 重新执行仓库、双语文档、定向行为、打包和已安装插件检查。

## 恢复

小型源码工作树会有意省略 Windows 可选依赖载荷。使用[水合脚本](../scripts/hydrate_release_payloads.py)依据锁定清单恢复：

```powershell
python -X utf8 scripts/hydrate_release_payloads.py
```

锁定的来源、大小和摘要约束见 [payload-bootstrap.json](../assets/payload-bootstrap.json)。会场二进制缺失时必须保持显式 `ONLINE_ACQUISITION_REQUIRED` 状态，并依据 `assets/venue-evidence/registry.json` 的 URL 与哈希重新获取。离线归档只是便利副本，不是第二个规范来源。

## 验证

只有同时满足下列条件，清理才可判定通过：

- 权威发布包哈希未改变；
- 所有冷证据 ZIP 均通过 CRC 与路径安全检查；
- 已跟踪的会场注册表仍存在，而被忽略的二进制已移除；
- 在缺少可选 payload 时，仓库与已安装插件行为仍通过；
- Windows 打包在水合前明确失败于 payload 预检，而不是静默生成残缺包；
- 已删除的生成目录确实不存在，结论账本明确报告哪些原始文件不可恢复。

## 边界

存储清理不是新的实证证据，不能提升既有科研主张。压缩后的开发回执仍然只是开发证据。只有当原始数据可复现或已被取代，而且决策相关结论、来源、计数和哈希均已保留时，才允许只保留结论。凭据、私有提示词、提供方回复和用户数据绝不能进入清理归档。
