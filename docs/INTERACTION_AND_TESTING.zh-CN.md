# 交互设计与写作／作图测试指南

## 原始交互设计

原设计是一个主智能体负责的自然语言协作：用户给目标与材料，智能体选择有用组件，
实际执行，审阅真实结果，交付文件。P0／P5／P6／P8 历史计划解释了演进；它们过去
强制的哈希／收据门槛，已被当前 Skill、组件接口和 2026-10-22 简化方案取代。

主智能体通读请求，保持用户范围与科学含义，语义选择有用主责而非关键词分类，
只问真实缺少的用户决策。计划、指令台账、模块记录和状态查询都是可选辅助，不是
修改文件或结束任务的前提。普通文件变化不会使整个项目失效。相关的引用支持、
数值、真实编译和实际审阅意见仍要检查，不能把“简化流程”理解为不核对事实。

专门的交互验收模式是：主智能体每次给执行智能体一条自然语言请求，检查真实
回答／产物，反馈后再进入下一项。从组件安装开始；发现问题就在原目录修复更新，
原样重测。不能用 mock 冒充对话，也不把整个验收流程丢给另一个会话无人跟进。

## 选择入口

写作用 `$academic-language-guard`；作图用 `$academic-figure-guard`。
由智能体调用工具，不让用户填 JSON 或复制内部标识／摘要；也可自然语言触发。

测试最新源码时，提供实际检出目录，要求读该目录的 `SKILL.md` 与相关子 Skill。
已运行的安装缓存可能更旧，即使版本号相同。读新说明不会热替换旧 MCP 进程。
应说明源码修订与实际执行入口；测试指定安装时，开新会话／服务器。

只安装需要的组：`component_install.py --components writing figures
--target <absolute-directory>`，自动带 core。同目录更新；已有 Python／TeX／Lean
能用就复用，仅在需要并获授权时装依赖。本次源码变更不重装插件或修改 Hook 信任。
见[组件安装说明](../references/component-installation.md)。

## 测试写作

先给一段或一节真实材料：

~~~text
$academic-language-guard
使用我指定的 Research Guard 源码目录。润色附件 Introduction，交付修改后的
Markdown 和简短实质修改说明。保留数字、引用、否定、因果强度、不确定性和局限；
不编实验。没指定 venue 就用通用学术风格，不把本次润色变成无关创新性检索。
~~~

测试参考文献驱动写作时，提供实验记录、现有大纲、范围／字数预算、保护信息及
明确日期门槛。参考资格三选一：中科院一区且引用 >10；CCF B／A 且最佳论文提名
或更高；CCF A 且 oral 或更高。用带日期的一手证据核对资格，并分别比较研究对象、
方法、内容的相似性。

迁移推理组织，不复制措辞：覆盖十一层逻辑、完整词／句／段对应、全文一致性，
及参考图表的功能；保持用户大纲。三名不同的真实智能体分别审逻辑匹配、防御性
表达和科学充分性，留下对话与发现，明确缺少的实验。交付七类：修改稿、官方
paper kit 编译 PDF、待补实验／解释、参考文逻辑分析、细粒度对应表、可运行结构
逻辑检查器及输入；涉及数学且本地 Lean 环境支持时，再交一份实际编译的完整 Lean。

有用接口为 `language_assist` 和
`reference_writing_action=plan/register_reference/submit/audit/status`。
普通修改沿用 ID 和目录，不要求摘要、匹配收据或强制重建计划。`status` 读取保存
结果，不是一次新审阅。

防御性句子先问：谁用它、改变什么理解／决定、删除后什么会误导。删除无用过程
叙述，收敛重复限定，把有用边界移到主张旁，或保留实质限定；图注与额外前言也
适用。只审查时给建议，不改源产物；内部工作记录仍可写入。检查实际改稿，结构
PASS 不等于语义正确。

## 测试作图

提供原图；若需贴合论文内容，再提供稿件或信息说明。参考图驱动可复制：

~~~text
$academic-figure-guard
阅读我给的论文和参考图，保留全部必要事实、文字与连线含义，优化布局和可读性，
不编结果。适合生成组件时使用当前实际可用的宿主图片工具。保留真实的信息／
风格／细节审阅、原生对比和裁剪，按要求交付七类产物。
~~~

参考图接口为 `figure_action=reference_plan/reference_audit/reference_status`。
每轮三名真实智能体分别审信息、风格、细节，至少两轮并修复最后发现；保留对话、
成对裁剪及像素观察。没有参考图时才使用各个已验证历史风格，不捏造参考文件。
七类交付：终图；审阅／对比记录；可运行像素检查脚本及结果；组件库；使用的网络
素材及链接／许可（未使用可为空）；论文逻辑映射；逐组件解释与逐项信息审计。
不能捏造独立审阅者，也不声称拥有实际不存在的工具／模型选择权限。

精确正式矢量图和统计图有另一条确定性路径：`figure_action=plan/render/audit`。
审阅实际最终尺寸 PNG，导出 SVG／PDF／300-DPI PNG。统计图要真实 CSV、正确估计量、
不确定性、重复单位和缺失处理，不能生成测量；机制图用显式节点／边。不应把用户
要求的生成式插图擅自换成该路径，也不把封装位图称为可编辑矢量图。

有 venue 时查询精确当前 year／track／stage 官方规范；没有就做通用论文风格。
普通修改不需重建计划或计算文件摘要，而应检查变动的视觉／科学内容。像素差异
是观察，不是自动风格判决。矢量 PDF 导出不需要 TeX。

## 用户决策与范围

用户决定最终方向／题目、缺失的实质事实、实际局限／伦理处理、依赖／供应商
费用及验收变更；智能体负责常规布局、实现与相关检查。不重复询问已有授权。
审查不等于允许改源文件；显式文件边界优先于方便的顺手修改。

保留用户要求的审阅轮次和验收，不恢复旧记账门槛。已有证据仍支持当前任务时
可以复用；相关变化、失败、未解疑点、必要在线事实更新或明确要求复现才重跑。
完成未知时先检查保存的产物与日志，不是索取特殊签名收据。默认时长到了不能
成为完成前停止的理由。

MIT。吸收完整履责、授权边界、直接方案、有证据才扩张、证据复用和读者有用表达。
不导入上游运行时代码、依赖、分类器或新执行门禁。

现有模块目录返回建议性的 `work_discipline`；显式选择时保存同一建议；
`UserPromptSubmit` 提供简短上下文。语言 Skill 复用保护信息与已有审阅，不另造
分析器。不恢复已移除的哈希门槛、强制台账、普通任务固定审计人数或自动状态失效；
用户指定参考流程的真实审阅仍保留。这些是智能体指导，不是新的运行时权限边界，
也不声称已经测得模型质量提升。

## 如何反馈测试结果

提供原话、源码／安装修订、输入文件、输出目录、实际现象及期望。写作指出改坏
的主张、丢失引用或薄弱段落；作图指出子图、标签或边并附实际 PNG。附实际报错和
审阅意见，不发凭据。区分工具链坏了、科学含义错了和视觉效果不好。
