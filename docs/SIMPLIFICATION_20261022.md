# 2026-10-22：去除哈希门槛和过度校验

正常使用 Research Guard 不再需要提交哈希、签名收据、安装回执、解释器摘要，
也不需要在修改文件后重新登记、重新封存或换目录安装。本次直接移除了对应
代码分支，没有新增“严格模式”把旧流程留作默认路径。

## 实际行为

- MCP 的公开参数和结果不再要求或暴露摘要封条；旧摘要参数仅作兼容，忽略其值。
- 同目录安装可以增减组件并保留用户文件。已有 Python、TeX、Lean 可直接使用。
- Hooks 提供短提示，不再用登记、计划、验证或旧状态阻断编辑和结束回复。
- 状态查询读取既有结果。显式重跑/提交读取当前内容，可以沿用原ID和输出目录。
- 论文、翻译、图、数学和实验记录不再因为字节变化自动失效；新提交仍核对当前
  数值、引用和实际执行结果。错误证明或不匹配的证据不能被写成成功。
- 普通文档修改不需要更新摘要、精确复刻章节标题或匹配一串固定源码 token。
- 去掉固定角色数量、理由字数及父进程128/64MiB门槛。父内存只记录，实际子任务
  的超时与显式资源限制保留。隔离安装不再默认套448MiB进程树RSS限制；
  只有指定`--max-memory-mib`时才限制该安装阶段内存。
- 实验日志不强迫补写来源没有提供的协议或逐项时间；测量接受 `name/metric`、
  `source_file/source`。计划直接说明所用字段。

用户指定的参考写作三角色审核、参考图每轮三角色审核及七类交付要求仍保留。
图像分析用于识别重复图片的内部指标、去重ID和Git版本标识不属于用户回填门槛。

## 推送后的跨平台修正

首次GitHub CI暴露了两个本机全量回归没有覆盖的环境差异：Windows短路径和
macOS临时目录别名导致相对路径计算失败；Linux隔离安装在可用内存充足时，
被固定448MiB进程树RSS限制中止。保留了首次失败的实际日志。

运行器现统一规范化工作根与测试路径，Windows实际junction已复现修复前失败、
修复后两次请求均执行成功。隔离安装默认只记录RSS，保留真实退出码和超时，
用户显式指定内存预算时才限制。新增六项实际进程机制回归：超过旧448MiB的
子进程成功、显式小预算终止、超时终止自己的子进程树及错误日志保留等。
这些用例已加入四平台CI；CI结果以对应提交的实际运行记录为准。
这组故意超过普通测试工作进程预算的用例独立执行，避免先被外层预算中止。
