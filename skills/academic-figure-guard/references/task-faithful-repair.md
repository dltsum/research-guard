# Task-faithful repair and compact revisions

Read for code/task UI illustrations, obsolete-content cleanup or a requested
compact layout. Use the existing repair playbook and fill procedure; this adds
no rendering route, fixed compression ratio or extra review rounds.

## Keep one sourced example across the figure

Read the task's provenance and final-delivery notes before replacing generic
example content. Map the actual task/repository, source and target versions,
file paths, inclusive line ranges and literal excerpts to each affected dock,
editor, preview, proposal label, tool inset, submission and magnification.
Verify against available source records, not the image's plausible-looking text.
Keep selected lines distinct from surrounding context. An intentionally partial
signature is a reference span, not a complete executable function to invent.

Label illustrative proposals, observations and receipts as schematic. A sourced
example or exact-match scan is not a model run, score or successful validation.
Keep author-only oracle material out of depicted agent inputs. Use actual schema
keys but omit unavailable values explicitly; never fabricate digests or receipts.
Existing version/commit identifiers may locate source objects without new hash
computation. If evidence is unavailable, report the missing mapping rather than
inventing source content. Do not copy private task records into the shared Skill.

## Remove the complete obsolete footprint, preserve the component

Inspect the old text at native resolution: include punctuation, braces, descenders,
antialiasing fringes and remnants beyond the main text rectangle. Restore the
underlying surface over that complete footprint while preserving adjacent icons,
document folds/stacks, borders and new labels. Check before/after crops for both
residual text and clipped icons; filling a nominal text box alone is insufficient.

Inspect pale rings, arcs and corner marks in context. Compare with the approved
reference and intended glass lighting: an accidental duplicate circle or leftover
overlay is not automatically a glass highlight, and a deliberate highlight is
not automatically noise. Remove only the unsupported artifact; retain intended
shading. A color threshold cannot decide artistic intent. Do not reclassify a
failed flat surface as intentional glass merely to pass the checker.

For window-frame/header junction halos or malformed neighboring window controls,
inspect layer order as well as color. In an authorized local chrome repair, a
constant-color annular inset can preserve the outer perspective; it is an option
for the observed defect, not a universal treatment. Repainting chrome must not
cover title glyphs or arrows crossing the frame. Declare known foreground
exclusions from geometry or restore those foreground elements at their original
layer order; inspect their continuity and the surrounding repaired band. Do not
exclude the unwanted halo itself or flatten intended glass lighting.
Restore the foreground footprint, not an oversized rectangle that also brings
back obsolete background and creates square seams. Where original raster arrows
must be retained, declare their shaft/head polygons including antialias fringes;
do not assume repeated generated arrows share an identical centerline. Include
dashed callouts crossing the frame, not only solid workflow arrows.

## Compact without losing meaning or readability

Honor the specific dimensional request. The motivating image requested a slight
height reduction only; do not generalize that to other figures or fix a ratio.
An explicitly requested slight aspect-ratio change is local authorization, not
a default aspect-warp policy; inspect resulting text and component distortion.
Prefer moving components and reducing excess padding to squeezing glyphs/icons.
Preserve readable font sizes at intended manuscript width, aspect ratios of
components, line spacing, port roles, arrowheads and collision-free geometry.
Use whitespace for a missing task-relevant locator, source/target correspondence
or necessary explanation only when it adds information; do not duplicate code,
invent metrics or add ornamental UI just to fill space. Useful whitespace may stay.

After resizing/resampling, inspect the actual final export, not the pre-resize
candidate. Rebuild/remap and inspect crop coordinates, flat interiors, text/icon
exclusions, boxes and connector anchors in final pixel coordinates. Interpolation
may spread foreground fringes beyond naively scaled masks. Keep declared color
expectations; do not hide defects by widening exclusions based on pixel color.

Reuse `scripts/figure_pixel_audit.py` with the final candidate and current geometry.
It reports SIZE_MISMATCH for unlike-size comparisons while still measuring the
candidate's declared fills. An old PASS, old eligible-pixel count or zero changes
outside the prior edit mask cannot certify a resized candidate. Preserve the old
report; save a fresh report and inspect final-size readability, geometry and paired
crops. The checker neither discovers omitted surfaces nor distinguishes rings
from glass. A fill PASS cannot certify icon preservation, semantic correctness or
print readability; unavailable review remains NOT_RUN. Record what was actually
checked and which retained or excluded pixels remain outside that claim.
